================================================================
STORAGE DECISION (user asked: "SQLite?")
================================================================
Chose a local JSON file (elements.json), NOT SQLite.
Reason: the dataset is 118 fixed, read-only rows. JSON is
dependency-free (no npm install, no native module, no
experimental node:sqlite flag), loads instantly, and is easy to
edit by hand — it matches the project's minimal/local/fast rules.
SQLite would add setup and moving parts for no benefit at this
scale. If the data later grows or needs real querying/relations
or writes from the app, we can migrate to SQLite then.

================================================================
DECISIONS
================================================================
1. Element pages are rendered DYNAMICALLY by server.js from

   file count low (project rule: "as few files as possible").

   grid and the server-side pages read it.
3. Grid cells are now <a href="N.html"> links. The symbol->number
   hover behaviour is unchanged.
4. Each element page has a small "← Periodic table" back link.

================================================================
HOW IT WORKS
================================================================
- Grid: app.js fetch("elements.json") -> one <a> per element,
  href = num + ".html", positioned via grid-column/grid-row.
- Click -> browser navigates to /N.html.
- server.js matches ^/(\d+)\.html$, looks up the element by number
  in elements.json, and returns the page HTML. index.html and the
  other static files are served normally.

================================================================
HOW TO RUN
================================================================
1. Open a terminal in the chem folder.
2. Run:  node server.js
3. Open: http://localhost:1429/index.html
4. Hover an element to see its number; click it to open its page.
