Add the relative atomic mass Ar to every element card.
Round it to a whole number for all elements (oxygen -> 16).
Chlorine alone keeps one decimal place.

================================================================
DATA — WHERE THE NUMBERS COME FROM
================================================================
IUPAC standard atomic weights, abridged values, taken from
Wikipedia "List of chemical elements" (the Atomic weight (Da)
column). For the 38 elements with no stable isotope the table
prints the value in square brackets — that is the mass number of
the most stable isotope, and that is what was stored:
  Tc 97, Pm 145, Po 209, At 210, Rn 222, Fr 223, Ra 226, Ac 227,
  Np 237 ... Rf 267, Db 268, Sg 267, Bh 270, Hs 271, Mt 278,
  Ds 281, Rg 282, Cn 285, Nh 286, Fl 289, Mc 290, Lv 293,
  Ts 294, Og 294.
Three of these differ from the values often quoted from memory
(Tc is 97 not 98, Sg is 267 not 269, Hs is 271 not 269), which is
why the table was fetched rather than typed from recollection.

================================================================
DESIGN DECISION — STORE EXACT, ROUND ON RENDER
================================================================
elements.json keeps the EXACT weight (H 1.0080, O 15.999,
Cl 35.45, Fe 55.845). The rounding is a DISPLAY rule in server.js:

  const AR_DECIMALS = { 17: 1 };
  formatAr(el) -> el.ar.toFixed(AR_DECIMALS[el.num] || 0)

Why not store "16" and "35.5" directly:
  - the data file stays truthful — nothing is lost, and a later
    task (molar mass, reaction arithmetic) can use the real value;
  - the chlorine exception is one entry in one table instead of a
    special case buried in 118 rows;
  - giving any other element a decimal is a one-line change.
This is the same pattern the project already uses for metal /
noble: the fact lives in the JSON, the presentation in the code.

================================================================
NOTE — ONE HALFWAY VALUE
================================================================
Dysprosium is exactly 162.50, the only element in the table that
lands on a .5 and therefore the only one where "round to a whole
number" is ambiguous. It is rendered as 163 (round half up, the
rule taught in school). If the textbook in use prints 162, that is
a single number to change in elements.json.
Chlorine, 35.45, would have rounded to 35 — which is exactly why
the task asks for one decimal there: 35.5 is the number every
Russian school table prints, and the one that makes HCl = 36.5.
