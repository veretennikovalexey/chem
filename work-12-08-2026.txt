================================================================
WHY A PLAIN COPY WAS NOT ENOUGH
================================================================
server.js resolved everything from __dirname. Copied into server/
as-is it would look for elements.json and index.html inside
server/ and fail on the first request. Three changes, nothing else
touched:

1. ROOT is gone, replaced by two anchors relative to the file
   itself, so the server can be started from any folder:
     PUBLIC = path.join(__dirname, "..", "public")
     DATA   = path.join(__dirname, "..", "data")
2. Static files are served from PUBLIC, and the traversal guard is
   now path.resolve + startsWith(PUBLIC + path.sep) instead of the
   old string test against ROOT. The old test would also have
   accepted a sibling folder whose name merely starts with the
   same text (public-old); the new one compares real resolved
   paths, so a request can never climb out of public/ into data/
   or server/.
3. A route for /elements.json.

Point 3 is the one real design decision. app.js and short.js both
do fetch("elements.json"), but the file now lives in data/, which
is deliberately outside the static root. The two options were to
keep a second copy in public/, or to serve the one in data/ from a
named route. The second wins: CLAUDE.md's "Data storage" rule says
elements.json is the single source of truth, and two copies of it
is exactly the bug that rule exists to prevent. It also cost less —
four lines in server.js, and app.js / short.js stay byte-identical
to what they were.

The URLs did not change at all: /index.html, /short.html,
/style.css, /app.js, /short.js, /elements.json, /N.html. Port is
still 1429, so chem.url still works.
